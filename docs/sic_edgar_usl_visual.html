Data quality

Primary keys pass

company.cik and sic_code.sic_code each have an auto-generated PK rule. No invalid records.

One foreign-key failure

IBM reports SIC 3570. company_dns has no such code, so SHOW DQ ALL INVALID TABLE returns that one row. The other six pass.

Wording is not a DQ rule

Five companies match on code, not on text (& vs and; EDGAR Retail- / Services- prefixes). The FK does not catch that.

Where the data comes from

Two public REST APIs register as Lightning databases. Each USL table is one ACTIVATE query. The foreign key lives only inside the USL, drawn between the two tables on the right.
